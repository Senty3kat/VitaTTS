# Vita TTS — заметки для Claude

Быстрый синтезатор речи для PS Vita (хомбрю, VPK) для музыки и живых выступлений. Автор — Senty3kat (общение на русском,
не программист, Vita с хомбрю). Код на C (gnu11), vitasdk + vita2d. Комментарии в коде пишем по-русски.
Подробная история решений и состояние на 17.10.2026 — `docs/HISTORY.md` (читать при входе в проект).

## Как работаем

- Перед каждой итерацией смотреть свежие коммиты соседних репозиториев автора: `Senty3kat/VitaSampler` (основной донор: аудиопоток,
  PNG-скины и `design/`, свои шрифты TTF в VPK, `host/preview`), `VitaStrummer` (хост-тесты, блок 256, UI-приёмы), `VitaMIDI`.
  Там же свои `CLAUDE.md` с правилами, которые тут тоже действуют.
- Сборка VPK — GitHub Actions (`.github/workflows/build.yml`). Логи Actions из сессии недоступны (403): причину ошибки видно только по
  ответу автора, поэтому workflow сам печатает блок ошибок по каждому варианту сборки в конце лога. Просить у автора именно его.
- Локально vitasdk нет. Проверка без него: `make -C host check-all` (строгая проверка синтаксиса `main.c` с заглушками SDK в `host/stub`,
  сигнатуры как в vitasdk; неявные объявления и int-conversion — ошибки). Тот же шаг выполняет job `host-check` в Actions.
  Новые вызовы vita2d/psp2 сначала добавлять в `host/stub` с точной сигнатурой из vitasdk.
- Ветки Pico/eSpeak (`HAVE_PICO`, `HAVE_ESPEAK`) локально не проверяются (нужны их заголовки): после правок там особенно внимательно
  читать код и просить автора прислать лог сборки.
- Автор тестирует на настоящей Vita. Всегда писать, что на Vita не проверялось, и давать короткий чек-лист, что проверить.
- Автору удобны инструкции вида «замени файл X целиком, сделай commit». Теперь файлов и папок можно делать сколько нужно.
- Коммит в `main`, в конце сообщения: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` и строка `Claude-Session: ...`.
  Если автор просит «пока не заливай» — только локальный коммит.
- Отчёт автору — по-русски, коротко: что сделано по пунктам, что проверить, чего ещё нет.

## Устройство

| Что | Где |
|---|---|
| Всё приложение (UI, потоки, движки, слоговый режим) | `main.c` (~1000 строк) |
| Сборка, выбор вариантов движков | `CMakeLists.txt` (`-DWITH_PICO/ESPEAK/SAM`), `.github/workflows/build.yml` |
| Разведка RHVoice (ручной запуск) | `.github/workflows/probe.yml` |
| Заглушки SDK и проверка без vitasdk | `host/` |
| История, референсы интерфейса | `docs/` |

- Движки: Pico (SVOX; EN US и UK, у каждого своя система Pico), eSpeak-NG (RU, JA, EN; стили голоса m3, m6, f2, f4, croak),
  SAM (C64, английский + самодельный русский через «буквы → фонемы»). Язык выбирается автоматически: кириллица → русский,
  японские знаки → японский, иначе английский голос.
- Звук: синтез пишет в кольцевой буфер (`RING`, ~21 с, 48 кГц), отдельный аудиопоток с повышенным приоритетом выдаёт его,
  предбуфер `PREBUF` (0,4 с), при недогрузе — тишина и повторный набор. Ресемплер в 48 кГц — оконный sinc.
  Выходной порт — **тройная буферизация** (одиночный буфер давал треск — не возвращать). Громкость: Select+↑/↓, 20–250 %.
- Питч «как у сэмплера»: меняется настоящая высота, длительность сохраняется (скорость движка подстраивается).
- Слоговый режим: фраза один раз синтезируется целиком в `phr[]` и режется на слоги по провалам громкости; слоги играются по кнопке
  или касанию задней панели, есть BPM, квантайз, сетка 1/4–1/16, авто-режим, чувствительность нарезки.
- Данные eSpeak в VPK ограничены (en-US, ru, ja и 5 вариантов голоса): иначе установка идёт очень медленно из-за числа мелких файлов.
  Файлы с пробелами в именах упаковщик VPK не принимает — workflow их удаляет.
- История 5 фраз хранится между запусками, окно ввода многострочное до 500 символов (`IMEMAX`).

## Принятые решения (не ломать без запроса автора)

- Приоритет — скорость ввода и отклика, а не «естественность»; голоса нужны ретро и роботизированные (Kraftwerk, Benassi), а не нейросетевые.
- Английский в строгом приоритете; русский и японский — через eSpeak, русский ретро — через SAM.
- SAM оставлен **только** один голос (C64): остальные пресеты булькали и автору не понравились. Куски текста для SAM — до 70 символов
  (буфер фонем SAM — 256 байт, длинные куски его переполняли и роняли приложение).
- Klatt-стили eSpeak в этой сборке шипят — убраны. Параметр Range (живость) ничего не давал — убран. Не возвращать.
- Питч и скорость работают на всех движках одинаково, управление: ←/→ скорость, Select+←/→ высота.
- Слоговый режим автору очень нравится — его поведение и кнопки не менять без запроса.
- Сборка пробует варианты по очереди (Pico+eSpeak+SAM → без SAM → Pico → eSpeak) и пишет в лог строку `Собрано: pico=… espeak=… sam=…`.
  Не убирать это поведение и печать блока ошибок.
- Интерфейс пока на английском (системный шрифт); кириллица и кана в нём отображаются не на всех прошивках, озвучка работает всегда.
- Стиль нового интерфейса: референс «+VITA» (`docs/ui/ref/`): кремовый корпус, жёлтый ЖК-экран с рамкой, кремовые и жёлтые объёмные
  кнопки, цветные чипы, ползунки, большая кнопка GENERATE/SPEAK. Раскладка — из винтажного варианта. Автор просил брать готовые куски
  из картинки, но в программу ничего из этого ещё не внедрено.

## Известные проблемы и сборка

- `vita-elf-create: Cannot allocate ... segment 1 overlaps` — код кончается у границы страницы; лечится подкладкой размера (`.space N`
  в `text_pad`, как в VitaSampler), если вернётся.
- В workflow пакет называется `libvita2d` (не `vita2d`), у pacman нужен `--noconfirm`. У VitaSampler сборка быстрее: он собирается в готовом
  контейнере `vitasdk/vitasdk:2026.08` — можно перейти на него, если установка VitaSDK в workflow продолжит капризничать.
- Pico и eSpeak требуют собственный `endian.h` для Vita (в CMakeLists); eSpeak собирается без `compilembrola.c` и `sPlayer.c`.

## Открытые вопросы и планы

- Проверить на Vita: русский через SAM (последняя правка), SAM C64 после уменьшения кусков, скорость установки VPK после сокращения данных.
- Нормальный русский голос: RHVoice (SCons, Boost, C++17, голоса в отдельных репозиториях; риск по скорости). `probe.yml` для разведки
  автор ещё не запускал. Решение о порте не принято.
- Японский через SAM (кана читается почти слогами) — предложено, не сделано. Ударения для русского SAM без словаря не ставятся.
- Новый интерфейс по референсу «+VITA»: PNG-атлас спрайтов и 9-slice в vita2d (как в VitaSampler: `tools/gen_assets.py`, `design/`),
  свой шрифт TTF в VPK. Начинать с основного экрана.
- Пресеты скорости и высоты на кнопки для выступлений. Разделить `main.c` на модули (по образцу `VitaStrummer/src`) — только вместе
  с расширением проверки в `host/`.
